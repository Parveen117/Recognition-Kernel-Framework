This page is the canonical map of the mathematics carried by this repository. It separates **algebra**, **calculus and geometry**, **theorem spines**, **domain adapters**, and **evidence layers** without moving or renaming source-pinned files.

Within Recognition Kernel Framework work, use the native objects and relations indexed here as the default internal mathematical language. A classical analogue may illuminate an object, but it does not replace that object. An identification with a classical construction is available only where a linked theorem supplies the required intertwiner, reconstruction, normalization, or equivalence.

This index is a map, not an evidence upgrade. The exact theorem file controls its hypotheses and conclusion; the certificate controls only its declared executable obligations; the claim-boundary file controls what remains open.

## 1. Reading grammar

Read every Recognition Kernel argument in this order:

```text
native state / carrier
-> recognition target
-> lawful transition or morphism
-> observer and declared memory
-> target-relevant blind quotient or open residue
-> repair / completion / refusal
-> theorem status and reproducible certificate
-> classical or physical interface, only if separately proved
```

The core operational tuple is

\[
(S_d,R_d,E_d,\tau_d,K_d),
\]

with the controlled meanings in [Terminology and Filing Alignment](TERMINOLOGY_AND_FILING_ALIGNMENT.md). The public umbrella is the **Recognition Kernel Framework**; **RNKE** is its operational engine; **Recognition-Seam Calculus**, **Morphic Algebra**, **Morphic Calculus**, **Morphic Operator Geometry**, **Recognition Topology**, **Singularity Calculus**, **EMK**, **UGD**, **RMG**, and **ECL** are distinct mathematical or implementation layers.

### Non-collapse rules

Keep these distinctions explicit:

```text
native object                         != chosen representation
transition / morphism                != clock parametrization
recognition target                   != observer output
identity                             != entailment
principal holonomy                   != lifted branch memory
flat chosen clock                    != absent native transition
regular curvature channel            != seam-supported singular channel
finite certificate PASS              != universal theorem proof
repository inclusion                 != external independent validation
```

### Evidence vocabulary

Use evidence labels on separate axes:

```text
mathematical axis:  DEFINED / PROVED / PROVED UNDER HYPOTHESES / OPEN / REJECTED
certificate axis:   PASS / INCONCLUSIVE / FAIL / STALE / NOT IMPLEMENTED
formal axis:        KERNEL-CHECKED / NOT FORMALIZED
review axis:        SOURCE-PINNED / INTERNALLY AUDITED / EXTERNALLY REVIEWED OR NOT
```

Never convert a label from one axis into a stronger label on another axis.

## 9. AI and contributor reading protocol

For any future question or development task:

1. Start with this index and choose the native mathematical family.
2. Read the exact theorem capsule, not only its filename or summary.
3. Declare the carrier, cut, target, observer, memory, and allowed transition.
4. Preserve native terminology such as Śūnya, Cut, Morphisum, Bindu, Lopa, Smriti, seam, residue, and recognition target where those are the defined objects.
5. Do not translate a native object into a classical analogue unless a linked theorem proves the bridge.
6. Check the theorem's own claim boundary and the [global boundary](CLAIM_BOUNDARY.md).
7. If citing a PASS, name the exact certificate and what its finite obligations cover.
8. If using a historical manuscript, consult its RNKE claim ledger before promoting a statement.
9. Cite the repository commit or release used for the argument.
10. When a required bridge is missing, label it `OPEN` rather than filling it by analogy.

## 11. Maintenance rule

Any change that adds, removes, renumbers, supersedes, or materially reclassifies mathematics must update this file in the same commit. It must also update the relevant theorem README, certificate index, provenance record, and claim boundary when those surfaces are affected.

The automated test `proof_lab/test_mathematics_index.py` checks that every numbered theorem and every public parallel theorem spine is represented and that every local Markdown link resolves. This keeps the map attached to the territory.
