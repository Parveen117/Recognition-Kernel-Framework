# Repository Mathematics Instructions

Before answering a mathematical question or changing a theorem surface, read `MATHEMATICS_INDEX.md` and the full preserved register it links, then the exact theorem and claim boundary.

The shared operator engine has one active home: `operator_foundation/` on `main` in this repository. Read `operator_foundation/CANONICAL_HOME.json` and its README first for operator development. Do not resume a historical MP or RKF branch as a second active engine. Runtime code and operative proofs are self-contained. The `sources/rkf_reference` tree is immutable public provenance, not an editable engine copy.

Use Recognition Kernel terminology and its native premise order. Typed cuts, cut scalars, derived iota, lawful composition, targets and residue memory precede representations. Do not replace these with classical analogies. An ordinary Hilbert space, physical clock or metric may only enter through an explicitly admitted representation or adapter. A native pairing already derived in the source is not discarded merely because it has a classical chart.

Keep theorem, computational, formal/Lean, provenance and external review status separate. A finite PASS is not a universal proof. Source inclusion does not upgrade a historical claim. Preserve existing RH, K0, E4D-C and mass-gap boundaries unless a later exact canonical theorem changes them.

Preserve source-pinned paths and native terms, including Śūnya, Cut, Morphisum, Recognition, Bindu, Lopa, Smriti, seam and open residue. Update the mathematics navigation in the same commit as mathematical additions. Run `node operator_foundation/verify_all.cjs --check` for this engine and `python -m unittest proof_lab.test_mathematics_index -v` under the supported Python 3.11/3.12 runtime for navigation changes. Report a missing runtime or an unrun suite instead of claiming success. Never overwrite certificate pins merely to make a failing read-only check pass.
