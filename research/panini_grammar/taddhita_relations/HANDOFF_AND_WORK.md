1,000 in one run, retaining written-grammar priority and deferred tests/
replay. PG35 therefore closes the written selection layer at the end of
4.2–4.3 instead of stopping mid-family. All 313 numbered entries have an

## W2. Checks actually performed

Static checks compare the five authored registers with the complete pinned
4.2/4.3 ID sets, require one row per ID, and independently recompute both
set unions. They check JSON syntax, source-key identity, literal source
field equality, file digests, local document links and Git whitespace.
The source fields are copied from `git show` at the pinned commit rather
than from an unversioned live page. These are document/provenance checks,
not grammar execution, certificate replay or proof-assistant verification.

The final static accounting found **313 unique contract rows**, compared
**948 literal source fields** (316 sūtra texts and 632 commentary fields),
verified **22 pinned file identities**, and resolved **50 local links**
across the new packet and its added navigation links. The three extra
archived sūtras are inherited 4.1.76/82/83, with no new-count credit.

The review corrected source-significant distinctions including वुन् versus
वुञ्, mandatory एणी ढञ्, the non-causal human branch of 4.3.81, separate
कुमुद gaṇa ordinals, Hemanta's three histories, scoped material मयट्, and
inner versus outer affix deletion. Every preserved alternative retains
its source and original affix, even if an unaccented word observer would
display the same string.

Previous packets and runtime files are unchanged. No grammar tests,
independent generators, certificate replay, navigation tests or operator
suites were run. The documentation helper only transcribed already
written tables and compared text/sets/hashes; it did not derive Sanskrit.

An implementation of PG35 must accept a typed request with supplied
semantic/case evidence, lexical identity, accent, compound structure,
register, gaṇa witness and owned affix history. Return separate
`WRITTEN_SELECTION`/future implemented selection, `OPEN`, and
`NOT_THIS_RULE` outcomes. Preserve analytic-phrase optionality separately.

Required implementation properties:

1. Keep semantic admission distinct from lexical affix selection. A bare
   suffix lookup must not invent born-in, descended-from, authored-by,
   belonging-to or material relations.
2. Retain original upadeśas and addressed affix tokens. The same visible
   -ika does not identify ठक्/ठञ्/वुन्/वुञ् histories.
3. Use scoped exceptions and dependent alternatives. Unknown exception
   evidence cannot silently fall through to अण्. Do not expand all options
   as independent Boolean switches.
4. Key gaṇas by source and ordinal. Separate the two कुमुदादि lists; keep
   member conditions and बहुलम्/ākṛtigaṇa witnesses.
5. Implement transfer only with a resolved source witness. In 4.3.100
   copy base treatment too; in 156 copy the qualified elision treatment.
6. Preserve the scope reset at 4.3.134 and the PartOf restriction of 135.
   Retain the special dung relation and the register-specific मयट् rules.
7. Keep downstream accent, feminine, phonology and nominal inflection
   obligations explicit. A selection record is not a final-word PASS.

The JSON register is a reviewable structured specification, not a claim
that a compiler for its natural-language predicates has been implemented.
