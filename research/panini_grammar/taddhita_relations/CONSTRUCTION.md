# PG35 — Scoped selection and owned nominal operations

Author: Monty. 4 November 2026.

## C1. Written construction order

1. Resolve the intended semantic relation and its case support using
   [DOMAIN](DOMAIN.md). Reject neither the language nor the whole request
   merely because one rule fails. Preserve unresolved evidence as Open.
2. Open the relation's scope. Select the appropriate C, S, M or earlier
   family. The 4.3.134 reset happens before collecting M candidates.
3. Collect only selectors whose lexical, structural, semantic and register
   gates are proved T. Evaluate potentially superseding gates as well;
   any unresolved necessary exception prevents an unqualified default.
4. Resolve the table's explicit exception, restriction, additive and optional
   relations. Never globally sort rule numbers and keep the last suffix.
5. Append the selected **original** affix with its relation and source.
   Apply the clause's coupled substitution/augmentation and addressed
   लुक्/लुप् operation; retain ownership and original identity throughout.
6. Return the finite set of labelled derivational records, plus separate
   Open decisions and realization obligations. Only a later completed
   phonology/inflection construction may return a final word.

`Select(a)` replaces an applicable general selector unless the row explicitly
adds alternatives. `Add(a,b)` adjoins the specified choices, not their
cross-product with unrelated prior choices. `Optional(a; default)` supplies
two licensed routes from the same input. `Restrict(g)` changes admission
to a particular selector; `Block(r)` removes only candidate r. `Luk(t)`
and `Lup(t)` address affix token t. `Transfer(source,destination)` copies
the source-qualified operations but changes the semantic edge only as the
transfer rule authorizes. A stipulated nipātana is a finite named clause,
not productive replacement on any similar spelling.

The machine-readable [register](RULE_REGISTER.json) is a transcription of
the authored tables with these proof obligations. Its condition/action
fields are written specification, **not executable predicates**. No runtime
parser or generator is added by this packet.

## C2. Default and precedence are local

Let \(R(q)\) be the finite candidate set in the admitted scope. Write
\(r\succ_q s\) only for a source-backed exception/restriction on this
particular domain. A candidate survives if its gate is T and no proven
applicable overriding clause suppresses it. A specified additive/optional
edge creates its labelled alternative even where ordinary replacement would
remove the general suffix. If a potentially decisive gate is ?, return
Open for that decision rather than declaring the default victorious.

For example, 4.2.39's gotra वुञ् is not indiscriminately removed by the later
anudātta अञ् of 44; 45's discussion supplies the relevant ordering. The
army-name क्षुद्रकमालव has its specific अञ् clause. Conversely, 4.2.6's
nakṣatra-dvandva छ blocks the earlier general time लुप्. Both directions
of these exception relations matter; no one-dimensional priority queue
captures them.

The present contract constructs these local relations on the declared
domain. An unreviewed intersection of lexical classes is not claimed
resolved merely because one rule has a larger serial number.

## C4. Elision has a target and a kind

**शर्करा:** 4.2.80 supplies its attested ठच्/कक् histories. Rule 83
restores general अण् and allows लुप् of **that** affix. Rule 84 adds
ठक्/छ. This gives six source-authorized branch types. A blind optional
elision after every selected suffix invents extra readings.

**कठ:** 4.3.104 selects an inner णिनि in PromulgatedBy. Rule 107 gives

then a separate outer relation and selected affix; 4.2.64 gives **its**
लुक्. The final bare-looking stem retains two different affix histories.

**जम्बू:** 4.3.165's explicit अण् remains audible. The ordinary अञ्
fruit branch can receive 163's लुक्. Rule 166 supplies a distinct लुप्
route with its yuktavad obligation. Do not turn लुक् and लुप् into a
single empty string operation. In 167's हरीतकी class the source explicitly
retains base gender while the number follows the intended fruit referents;
one tree does not force a singular word for many fruits.

**कंसीय / परशव्य:** 4.3.168 selects outer यञ्/अञ् respectively and
targets inner nominal छ/यत् for लुक्. It does not delete the new material
affix or the root-derived constituents of कंस/परशु. The proper input is
the owned derivational tree, not a suffix guessed from the current spelling.

## C6. Material scope and exclusions

Start a fresh M view at 4.3.134. Thus हल in I can take ठक् (124), but
that alone cannot justify ठक् for material made from हल. The PartOf
branch of 135 applies to living beings, herbs and trees; other bases retain
only ModificationOf unless a particular rule, such as cow-dung 145,
supplies its own relation.

Rule 143's optional मयट् requires bhāṣā and excludes food/clothing. Rule
150 is an independent Chandas two-vowel constructor and can produce the
source's दर्भमय clothing. Rule 151 blocks that Vedic route for a short
उ anywhere in the base or for वर्ध्र/बिल्व. It does not block धूम merely
because long ऊ resembles उ in transliteration.

Rules 136, 152 and the repeated already-anudātta members of 154 explicitly
override appropriate मयट् candidates. At the same time 143 explicitly
allows कपोतमय/कापोत and लोहमय/लौह. Preserve the member-specific source
clauses instead of replacing the whole family by “later 154 always wins”.

At 155 a new material affix is अञ् only when the prior affix was ञित्
**and** itself a material/part affix. दैवदारव carries that history;
बैद as a patronymic does not, even though its history contains ञ्. This is
a second example where surface form and marker presence alone are too weak.

## C7. What this written result establishes

For admitted, source-resolved inputs the constructor returns exactly the
finite set of specified **selection histories**, relative to the local
scope/precedence decisions above. The rule tables and witnesses establish
bounded constructive cases for every one of the 313 IDs. They do not prove
unrestricted applicability to all lexical items, settle all commentary
disputes, complete accent/inflection, or certify an implementation. The
[native continuation](NATIVE_CONTINUATION.md) preserves this precise level
under the existing framework's zero-reading.
