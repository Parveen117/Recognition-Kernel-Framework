# PG17 — The joint pada/iṭ relation

Author: Monty. 2 November 2026.

## B1. Input objects on the native carrier

Use N1's native history modules and their type grades. Extend the PG16
frame by an exact formation label `Basic` or `Causative(ṇic-owner)`, a
root-group membership witness, the chosen commentary policy and an
optional-choice witness where a rule actually licenses one. Keep the
original teaching form, lexical identity, sense, semantic evidence,
temporal adapter, owned constituents and every applied event.

The completed word-level future interpretation is PG16 F3's
FutureGeneral → lṛṭ or FutureAnadyatana → luṭ. The agent controls
agreement in the basic sector; the causer controls it in the causal
sector. Nine person/number slots are inherited from PG16 E1–E6.
An unresolved semantic input remains Open. A grammatical option is a
positive branch from one completed input, not missing semantic evidence.

The domain excludes prefixes, special sentence constructions, accent,
Vedic usage, external sandhi, san/yaṅ and bhāva/karma expression. It
does not lift every exception for a homographic root into this domain.

## B3. Pada selection before the dependent iṭ decision

For svṛ/iṣ/nṛt the stated ordinary domain is P. For dhūñ use the
principal-result condition of 1.3.72: A when the principal kriyāphala
accrues to the agent, residual P otherwise. This is a resolved semantic
choice, not free P/A variation. Unknown principal-result evidence is Open.

For the five exact vṛt-group entries, ordinary A is supplemented by:

- **1.3.92:** optional P before sya/san. In PG17 only sya is admitted;
  the source also covers san and lṛṅ-related sya, which remain outside.
- **1.3.93:** for kṛp specifically, optional P also in luṭ. Its ca
  retains the earlier sya/san route; it is not a new prohibition there.

Thus all five have {A,P} in lṛṭ. In luṭ, vṛt/vṛdh/śṛdh/syand
have only A here, while kṛp has {A,P}. These are genuine options of
completed frames and differ from dhūñ's two beneficiary-conditioned
profiles. A luṭ P request for the other four is outside this basic
construction; a possible causative or prefixed use cannot repair that
request without changing its input type.

## B4. A dependent iṭ relation

Write 1 for the presence of the affix-owned iṭ augment and 0 for its
licensed absence. The base permission is 7.2.35, with the retained
ārdhadhātuka/val conditions. The selected source relations are:

| Root | lṛṭ permitted (pada, iṭ) | luṭ permitted (pada, iṭ) |
|---|---|---|
| svṛ | (P,1) | (P,0), (P,1) |
| dhūñ | (P,0),(P,1) in its P frame; (A,0),(A,1) in its A frame | Same conditioned alternatives |
| iṣ | (P,1) | (P,0), (P,1) |
| nṛt | (P,0), (P,1) | (P,1) |
| vṛt | (P,0), (A,1) | (A,1) |
| vṛdh | (P,0), (A,1) | (A,1) |
| śṛdh | (P,0), (A,1) | (A,1) |
| syand | (P,0), (A,0), (A,1) | (A,0), (A,1) |
| kṛp | (P,0), (A,0), (A,1) | (P,0), (A,0), (A,1) |

The reason for every departure from the base permission is explicit:

1. **7.2.44** supplies the svṛ/dhūñ and ūdit options. **7.2.70**
   overrides svṛ's option before sya, giving obligatory svariṣyati;
   it does not remove the svṛ option before tās. Kāśikā explicitly
   states this relation.
2. **7.2.48** supplies the option for our iṣ before a **t-initial**
   ārdhadhātuka. It gives eṣitā/eṣṭā in luṭ, while sya retains
   obligatory iṭ. The u-it rule 7.2.56 concerns ktvā and must not be
   imported as a general future option.
3. **7.2.57** gives nṛt an option before a **s-initial, non-sic**
   ārdhadhātuka. Thus nartiṣyati/nartsyati, but only nartitā in luṭ.
4. **7.2.59** prohibits iṭ after the first four vṛt entries before
   the relevant s-initial affix on the P branch. It defeats even
   syand's ūdit option there. The A branch of syand retains both
   options, explicitly illustrated by Kaumudī/Bālamanoramā.
5. **7.2.60** imposes kṛp's P prohibition before both tās and the
   s-initial ārdhadhātuka. Its A branch retains the ūdit option:
   kalpitāse/kalptāse and kalpiṣyate/kalpsyate are explicit in Kaumudī.

The source's broader analysis of “parasmaipadeṣu” includes cases with
kṛt and P-ending lopa. PG17 admits overt finite P/A only, where its
meaning is resolved. We do not promote this restricted matrix into a
general replacement for that wider source interpretation.

## B5. Why two independent menus are wrong

For kṛp the completed lṛṭ frame has three branches, not four:

\[
 \{(P,0),(A,0),(A,1)\}
 \subsetneq \{P,A\}\times\{0,1\}.
\]

The missing pair (P,1) contradicts 7.2.60. For vṛt the corresponding
two-branch relation is {(P,0),(A,1)}. Treating P/A and iṭ as unrelated
options invents two additional forms. Conversely forcing an aniṭ
spelling on every branch deletes legitimate A forms.

An implementation may explore an iṭ hypothesis before pada if it retains
the unresolved guard and later discharges it. It may not label that
hypothesis as an accepted grammatical alternative before doing so.
This is a dependency statement, not a universal claim that every valid
traditional derivation must use one textual rule order.

**Proposition B6.** For completed B1–B3 basic frames, B4 gives all and
only the pada/iṭ branches licensed by the adopted rules on this domain.

**Proof.** B3 exhausts the ordinary, principal-result and enumerated
optional-P cases. For each resulting pada, B4 either retains the base
iṭ permission, replaces it by a specifically cited two-way option,
or applies the local mandatory/prohibitory override. Every table pair
has that witness. The excluded pairs fail the named guard or prohibition.
The nine roots exhaust B2, so no further case remains. Multiplying each
admitted pada/future position, then each joint branch, by its nine
agreement slots gives the displayed sums. □

These counts are over completed frames and branch readings; they are
not counts of distinct strings, independent source attestations or
software executions. Nothing requires a speaker to choose the same
optional variant at every position in every separate utterance.
