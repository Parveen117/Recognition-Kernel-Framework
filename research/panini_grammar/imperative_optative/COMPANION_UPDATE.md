## Overlap with PG19 and the important state gap

T96 already describes bhū/gam/nī P loṭ/vidhiliṅ (54 positions), and the
corresponding two moods in T99 cover edh/labh A (36 positions). T129
consolidates those **90 overlapping modal positions**. PG19's 976 count
is the size of its own written domain, not 976 wholly new forms. We do
not subtract 90 and call the remainder a certified novelty census: other
repository overlap has not been exhaustively classified.

PG19 supplies the shared six-sense relation and bounded contextual rules,
controllers, addressed affix/augment ownership, expanded thematic and
athematic paradigms, causal/passive construction, and native proofs. A
matching basic thematic surface does not establish those additional claims.

At the inspected T129/T130 code snapshot, the **3.4.92 row adds āṭ but
does not set `s.pit = True`**. `pit` was initialized from the original
tiṅ and is explicitly changed for 3.4.87 hi, but not for the uttama
prescription. The table avoids a bad 7.2.81 rewrite through an additional
named-ending guard; that does not supply the missing grammatical state.
This is not a claim that its reported thematic outputs fail. It is a
concrete gap before extending that state to kṛ/krī: karavai/karavāvahai
require the strong pit path, whereas kurvīya/kurvīvahi require the weak
optative path. PG19's E/A construction derives both.

Two further distinctions matter for a future adapter:

- The current table compresses the surface-neutral suṭ/s-lopa pair in
  ordinary vidhiliṅ; its 3.4.107 row is restricted to A āśīrliṅ. T99 itself
  records the canceled vidhiliṅ suṭ. An adapter to PG19's full histories
  must supply those owned events or explicitly declare a quotient of them.
- Root, vikaraṇa and tiṅ marker conditions need separate addressed views.
  The current thematic guard is not a general substitute for them: outer
  liṅ ṅittva must not block root guṇa before pit śap, while athematic
  vikaraṇa queries must see the ending's appropriate kit/ṅit status.

Each table's fixed order is a selected implementation schedule. Finite
agreement does not prove a universal conflict/visibility scheduler. Both
tables should be adapters to the single canonical operator home; neither
introduces a second native operator foundation.
