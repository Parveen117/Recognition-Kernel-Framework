## W4. Required implementation properties

1. Treat relation/case, source policy and evidence as input, with T/F/?.
   Do not infer a named disease, historical group or compound class from
   spelling alone. Unknown decisive evidence returns Open.
2. Retain original marker identity and operation kind. Distinguish suffix
   कन् from base substitute कन्; तसि from तसिल्; ञ from अन्; and
   joined sandhi letters from original upadeśa.
3. Address ordinal affix augments separately from base augments. Preserve
   inner ordinal/possessive tokens when later कन्/degree suffixes are
   added, and delete only the specified token.
4. Use source-dependent branch sets. Some optionality retains मतुप् only;
   some admits four suffixes. Paired lists must not become free products.
5. Preserve pre-direction designation boundaries, case resets, near/far
   distinctions and explicit earlier alternatives. Local obligatoriness
   overrides a universal optional-affix interpretation.
6. Implement अकच् insertion and affectionate-name truncation on the
   retained structure. Count vowels on the specified source representation;
   more than two vowels is not the same predicate as more than one.
7. Require actual prior selection witnesses for 5.3.8 and 5.4.22 transfers;
   retain both source and destination events.
8. Separate transformation, ownership and gift frames. सम्-पद् does not
   inherit a च्वि option merely because साति allows it.
9. Make a compound ending part of its compound tree. Enforce each class
   restriction at 5.4.77 and retain the endpoint on 5.4.69's prohibition.
10. Keep source examples, written selection histories and complete surface
    derivations as different statuses. The register contains natural-language
    predicates; runtime compilation and independent checks are still needed.
